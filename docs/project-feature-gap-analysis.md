# PiSite 当前功能缺口分析

分析日期：2026-05-12  
范围：`backend/src/routes.rs`、`backend/src/handlers/*`、`frontend/src/App.tsx`、`frontend/src/pages/*`、`frontend/src/components/*`、现有 `docs/` 与部署配置。

## 1. 当前已经具备的能力

项目已经不是单纯官网，而是一个包含官网内容管理、客户端分发、服务器生态、捐赠授权和 API 管控的综合后台。

### 前台与内容

- 官网首页：Hero、核心特性、截图、FAQ、更新日志、赞助商、Footer。
- 中英文基础切换：已有 `home-i18n.tsx`，Hero 内容也已经开始支持英文配置。
- 更新日志页面：`/changelog`。
- 服务器投稿页面：`/servers/submit`，支持提交、邮箱验证码、所有者 Code 修改、下线。

### 后台管理

- 内容管理：Hero、核心特性、截图、FAQ、赞助商、站点设置、友情链接。
- 版本分发：Changelog、Tauri updater、包文件上传/重命名/删除、推送下载链接到 Hero。
- Minecraft 内容：Minecraft 资讯抓取、版本 manifest 同步、文章/活动 PUSH。
- 服务器生态：投稿审核、标签字典、在线状态 Ping、信令服务器。
- 安装统计：安装 ID、平台、内存、GPU、版本、周对比；GPU 映射表已可维护。
- 捐赠授权：用户、许可证、设备、激活记录、爱发电绑定与同步。
- 安全与 API：管理员初始化/登录、Turnstile、会话超时、API Key、公开 API 策略、访问日志与警告。
- 邮件系统：SMTP 配置、测试邮件、模板、邮箱过滤规则、投稿验证码、审核通知。

### 后端基础设施

- Rust + Axum + SQLite + SQLx migration。
- Docker Compose 部署。
- 上传目录分离：`admin`、`mc_covers`、`server_covers`、`packages`。
- 后台守护任务：Minecraft 抓取、版本 manifest、服务器状态 Ping、文章 PUSH 过期清理。

## 2. 高优先级缺口

### 2.1 数据备份、恢复与迁移安全

当前缺口：

- 没有后台数据库备份/下载/恢复入口。
- 没有上传资源备份策略，SQLite 数据和 uploads 目录需要一起备份，否则内容会断图或断包。
- migration 目前依赖启动时自动执行，缺少迁移前检查、迁移报告、失败回滚说明。
- 只有 fresh database migration 测试，缺少“旧版本数据库升级到当前版本”的夹具测试。

建议功能：

- 后台增加“系统维护”页：数据库备份、上传目录打包、备份下载、备份时间记录。
- 增加 `docs/deployment-upgrade.md`：升级步骤、回滚步骤、备份校验。
- 增加旧库升级测试夹具，覆盖已有生产库结构。
- 对 migration checksum mismatch 制定固定处理策略，避免线上环境因为改过 migration 文件无法启动。

优先级：P0。

### 2.2 后台操作审计与权限分级

当前缺口：

- 管理员只有统一 admin 身份，没有角色权限。
- 后台高风险操作没有审计日志，例如删除服务器、删除包、修改 API 策略、修改 SMTP、删除捐赠用户。
- 无法追踪“谁在什么时候改了什么”。

建议功能：

- 增加 `admin_audit_logs` 表，记录 actor、动作、资源类型、资源 ID、前后差异、IP、UA、时间。
- 后台增加审计日志页面，支持按模块/管理员/时间筛选。
- 增加角色：超级管理员、内容管理员、运营管理员、财务/捐赠管理员、只读观察者。
- 高风险操作增加二次确认或要求重新输入密码。

优先级：P0。

### 2.3 隐私、服务条款与用户数据说明

当前缺口：

- Footer 已有“隐私政策”“服务条款”文案，但前端没有对应页面路由。
- 项目收集下载 IP、安装 ID、平台、内存、GPU、版本、服务器投稿邮箱、捐赠授权设备等数据，但缺少公开说明。
- 没有用户数据删除/导出流程说明。

建议功能：

- 增加 `/privacy`、`/terms` 页面，并在后台维护文本。
- 增加“数据收集说明”：安装统计、下载统计、服务器投稿、捐赠授权分别收集什么、用途是什么、保留多久。
- 增加数据删除申请入口或至少提供联系邮箱。
- 为安装统计和 API 日志设计保留周期。

优先级：P0。

### 2.4 监控、健康检查与告警

当前缺口：

- 后台右上角 `System Online` 是静态展示，不代表真实服务状态。
- 没有 `/api/health` 或 `/api/admin/system/status`。
- 后台守护任务的最近运行时间、错误信息、处理数量没有统一展示。
- SMTP、Minecraft 抓取、服务器 Ping、爱发电同步等外部依赖没有健康状态视图。

建议功能：

- 增加健康检查接口：数据库、上传目录可写性、守护任务状态、外部依赖状态。
- 后台 Dashboard 展示真实系统状态。
- 守护任务统一写入 `system_job_runs` 表：job、started_at、finished_at、status、message、metrics。
- 错误达到阈值时在后台顶部展示告警。

优先级：P0。

### 2.5 登录安全与暴露面控制

当前缺口：

- 管理员 token 存在 `localStorage`，一旦前端 XSS 会有较高风险。
- CORS 目前允许任意来源。
- 登录只有密码与可选 Turnstile，没有后台登录失败限流/锁定/二次验证。
- JWT_SECRET 缺失时会临时随机生成，适合开发，但生产误配会导致重启后全员失效。

建议功能：

- 生产环境强制校验 `JWT_SECRET`、`DONOR_JWT_SECRET`、`DATA_ENCRYPTION_KEY`，缺失直接拒绝启动。
- CORS 改为从环境变量读取允许域名。
- 登录失败限流、IP 冷却、账号锁定、登录历史。
- 可选 2FA/TOTP。
- 增加 CSP、上传资源 MIME 校验与安全响应头。

优先级：P0。

## 3. 中高优先级产品缺口

### 3.1 公开服务器发现页

当前状态：

- 后端已有公开接口：`GET /api/server-submissions`、`GET /api/server-status`。
- 前端已有服务器投稿页面和服务器类型模型。
- 但前端路由中没有公开服务器列表/发现页。

建议功能：

- 新增 `/servers` 公开发现页。
- 支持搜索、版本筛选、标签筛选、在线状态、服务器类型、排序。
- 展示在线人数、封面、描述、标签、社交链接。
- 与 `/servers/submit` 形成闭环：发现服务器 -> 投稿服务器 -> 审核上线。

优先级：P1。

### 3.2 多语言支持仍不完整

当前状态：

- 前台框架文案已有 `home-i18n.tsx`。
- Hero 已支持部分英文内容。
- Features、FAQ、Changelog、Sponsors、Footer 友链、服务器投稿、服务器发现、文章 PUSH 等内容模型仍以中文/单语字段为主。

建议功能：

- 内容表增加统一 i18n 字段或独立翻译表。
- 后台内容编辑页使用语言分段按钮，统一维护中文/英文。
- 前台数据接口按 `locale` 返回对应语言，缺失时回退中文。
- 邮件模板也可增加多语言版本。

优先级：P1。

### 3.3 媒体资源库与孤儿文件清理

当前状态：

- 已有多个上传入口：Hero、Sponsor、Features、Server Cover、Package、Article Push。
- 文章 PUSH 过期后会清理相关图片。
- 其他上传资源缺少统一索引、复用、替换、清理能力。

建议功能：

- 新增“媒体资源库”：查看上传文件、尺寸、大小、引用来源、上传时间。
- 支持未引用文件扫描与安全删除。
- 上传文件统一记录到 `media_assets` 表。
- 对图片增加压缩策略、尺寸限制、格式白名单、重复文件识别。

优先级：P1。

### 3.4 文章/活动 PUSH 投递语义

当前状态：

- 已有后台文章 PUSH 管理、封面上传、过期清理、公开列表/latest 接口。
- 但目前更像“客户端拉取公告”，还没有完整 PUSH 投递语义。

建议功能：

- 增加开始时间、优先级、置顶、目标平台、目标版本、目标地区。
- 增加客户端已读/已展示回执，避免重复打扰。
- 增加展示频率控制：仅一次、每天一次、每次启动。
- 增加预览和测试投递。

优先级：P1。

### 3.5 前台失败态与空状态体验

当前状态：

- 多个前台组件接口失败时仅 `console.error`，用户不可见。
- 首页分块使用懒加载和 placeholder，但缺少错误恢复 UI。

建议功能：

- 前台统一 `DataState` 组件：loading、empty、error、retry。
- 对 Features、FAQ、Changelog、Sponsors、Hero、Footer 增加失败态。
- API 异常时展示轻量提示，不让页面静默缺块。

优先级：P1。

### 3.6 搜索、分页与规模化列表

当前状态：

- 部分后台页面已有搜索或分页。
- 一些公开接口直接返回完整列表，例如服务器列表、FAQ、赞助商、更新日志等。
- 安装统计只取最近 500 条。

建议功能：

- 公开服务器列表、更新日志、文章 PUSH 增加分页和筛选参数。
- 后台安装统计支持服务端分页、按平台/版本/GPU/时间过滤。
- API 日志和警告支持保留周期与分页导出。

优先级：P1。

## 4. 中优先级工程与运营缺口

### 4.1 测试覆盖不足

当前状态：

- 后端仅看到 migration fresh DB 与 SVG sanitizer 相关测试。
- 前端没有单元测试、组件测试或 E2E 测试脚本。

建议功能：

- 后端增加 handler 级集成测试：登录、内容 CRUD、服务器投稿、捐赠授权、API Key 策略。
- 增加旧库升级测试。
- 前端引入 Vitest/Testing Library，覆盖核心表单和 hooks。
- 引入 Playwright，覆盖后台登录、内容发布、服务器投稿、版本发布主流程。

优先级：P1。

### 4.2 API 文档与 SDK 说明

当前状态：

- 后端有 `api_catalog.rs` 用于公网 API 控制，但没有生成 OpenAPI 或公开文档。
- 客户端安装统计、捐赠授权、Tauri updater、服务器投稿都属于外部调用面。

建议功能：

- 生成 OpenAPI JSON。
- 增加 `docs/api.md`：认证方式、API Key、错误码、示例请求。
- 为客户端集成接口增加版本字段与兼容策略。

优先级：P2。

### 4.3 SEO 与分享优化

当前状态：

- 已有动态 SEO hook。
- 但没有看到 sitemap、robots、Open Graph 图片管理、结构化数据配置。

建议功能：

- 增加 `/sitemap.xml`、`/robots.txt`。
- 后台维护默认 SEO、页面级 title/description/OG image。
- 更新日志、服务器详情页、文章 PUSH 支持独立分享元数据。

优先级：P2。

### 4.4 发布流程与包安全

当前状态：

- 支持包文件上传、Tauri updater、签名字段、灰度配置。
- 缺少发布前校验、包来源记录和回滚说明。

建议功能：

- 发布前检查：版本号递增、平台包完整、签名存在、下载 URL 可访问。
- 包文件记录 checksum、大小、上传者、上传时间。
- Changelog 支持草稿/预发布/正式发布状态。
- 增加发布 checklist 和一键回滚到上一稳定版本。

优先级：P2。

### 4.5 运营自动化

建议功能：

- 投稿审核队列支持批量操作、备注、内部标签。
- 邮件模板支持变量预览和发送历史。
- 赞助用户支持到期提醒、批量导入、CSV 导出。
- Minecraft 资讯抓取支持手动编辑缓存条目、排除规则、来源健康度。

优先级：P2。

## 5. 建议路线图

### 第一阶段：上线安全底座

目标：降低数据丢失、安全误配和不可观测风险。

1. 数据备份/恢复与升级文档。
2. 健康检查与守护任务运行记录。
3. 后台操作审计日志。
4. 生产环境强制密钥校验、CORS 域名白名单、登录失败限流。
5. 隐私政策与服务条款页面。

### 第二阶段：补齐产品闭环

目标：让已有后端能力真正被前台消费。

1. 公开服务器发现页。
2. 完整内容 i18n。
3. 媒体资源库。
4. 文章 PUSH 投递控制与客户端回执。
5. 前台统一错误态与重试。

### 第三阶段：规模化运营

目标：支持更多用户、更多内容和更稳定的发布。

1. 服务端分页、筛选、导出。
2. E2E 测试与发布 checklist。
3. OpenAPI 文档。
4. SEO/sitemap/分享卡片。
5. 运营批量操作与自动化提醒。

7. 将 Features、FAQ、Changelog 增加英文内容字段，并在后台用分段按钮编辑。
